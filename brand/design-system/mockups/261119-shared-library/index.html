Shared library: the Shared tab and Publish

Two questions about the shared library (#88), from the approved spec. Each has its own options, and each is answered on its own. Everything else on the Programmes page stays as it is.

  1. The Shared tab: where the shared programmes sit, and what a row offers
  2. Publish: how an admin publishes, publishes again and unpublishes

Today is Thu 19 Nov 2026. The shared library holds Strength 5×5, Couch to 5K and Desk mobility. A shared programme names no one (S2). No option adds a colour: each uses the system's tokens and its existing cards.

Question 1 of 2 · any user

1. The Shared tab

Every signed-in user can see the shared library and copy a programme from it into their own library. The copy is theirs (S4): they adjust it with the start options or an agent, and start it from the Library as today. Each shared row shows the name, “Kind · N weeks · N activities” and the description, as a library row does.

A. A fourth tab, Shared, between Library and Add

Option 1A

Each row has one action, Copy to library (secondary, Lucide copy-plus). After a copy, an InlineMessage (success) at the top of the tab says “Strength 5×5 is in your library.”, with a TextLink, Open in Library, that opens the Library tab. The row stays as it was: copying again makes a second copy. The copy keeps the shared programme's name.

C. As A, with Preview before copying

Option 1C

The Shared tab as in A, and each row gains Preview (secondary, Lucide eye) before Copy to library. Preview opens the programme in place, framed in 2px ink as Preview and start is, with its plan: the ProgrammeGrid as the start's preview, weeks by number with no dates, at the programme's own values. Close and Copy to library (primary) end it. It costs a second action on every row, and a grid the Library's Preview and start shows anyway after the copy.

Question 2 of 2 · the admin only (John)

2. Publish, on the admin's Library tab

Only an admin publishes, and the server checks it every time (S1). Publishing copies the programme as it is now (S3); editing or deleting it in the library later changes nothing shared. Nobody else sees any of these controls. John's library holds Strength 5×5 and Couch to 5K, both shared, and Hip mobility, which isn't.

A. Publish on each row; a shared row says so

Option 2A

Each row gains Publish (quiet, Lucide share) after Delete. A shared row shows a “Shared” Chip after its name and offers Publish again (refresh-cw) and Unpublish (eye-off) in place of Publish. After a publish, an InlineMessage (success) at the top of the tab says “Strength 5×5 is in the shared library.” Folded, the row's buttons sit two to a row, as Duplicate and Delete do now.

John's Library tab, just after publishing Strength 5×5

Publish, from Strength 5×5 before it was shared: the server's preview, then Publish programme

The Dialog opens on the server's preview (preview by default), so what it shows is what will be shared: the name, the facts, the description, then each activity with its chip, notes and link (S5). Nothing is shared until Publish programme, which sends the preview's rev. If the programme changed since, the Dialog shows the fresh preview with an InlineMessage (info), “The programme changed since this preview. Check it, then publish.” Publish again opens the same Dialog titled “Publish Strength 5×5 again”, with the line “It replaces the shared copy from Tue 17 Nov. Copies people have made stay as they are.” and the button Publish again.

B. Publish in a row's overflow Menu

Option 2B

Each row gains a quiet IconButton, More (Lucide ellipsis, named “More for Couch to 5K”), after Delete. It opens a Menu with Publish, or Publish again and Unpublish for a shared row. The Chip, the Dialog and the ConfirmDialog are as in A. The row looks as it does today, and the publish controls are one press further away. This is the first Menu on a row; the Menu card covers only the account menu today.
